# 古蹟劣化多專家偵測系統規格書

> 文件狀態：Draft v1.0
> 適用範圍：古蹟建築表面影像之劣化偵測、量化、風險分級與人工複核
> 核心策略：每一種劣化由獨立「專家」模型負責；平台只負責標準化輸入、協調推論、結果融合與可追溯呈現。

## 1. 目標與範圍

### 1.1 目標

系統以一張或一批古蹟表面影像為輸入，平行執行各劣化專家，產出：

1. 像素級病害遮罩、位置與量化面積。
2. 每個病害實例的置信度、嚴重度與需複核標記。
3. 影像、構件、建築物三層級的病害彙整與風險判讀。
4. 可讓文資／修復專家檢查、修訂並回饋訓練資料的報告與審計紀錄。

本版正式處理五種劣化類別：`crack`（裂縫）、`loss`（缺失）、`shrinkage`（皺縮）、`craquelure`（龜裂）、`flaking`（起甲）。`stain`（汙漬）目前僅為待確認的候選標註，不納入 v1 模型訓練、正式推論、報告統計或驗收指標。架構必須支援日後經領域確認後新增汙漬、鹽害、霉菌、生物附著、風化、滲水痕等專家，不改動既有專家程式碼。

### 1.2 非目標

- 不以單張 RGB 影像直接宣告結構安全；結構判定仍須現場勘查與專業簽認。
- 不自動產生修復工法或施工指令。
- 不要求所有病害共享同一模型、同一資料集或同一閾值。
- 不取代人工標註；人工校正是資料治理與持續改善的一環。

## 2. 使用者與主要情境

| 角色 | 需求 | 系統權限 |
|---|---|---|
| 現場調查員 | 上傳影像、查看問題區、補充構件與拍攝資訊 | 建立案件、檢視結果、送審 |
| 文資／修復專家 | 判讀劣化、修正遮罩與嚴重度 | 複核、校正、簽認 |
| AI 維運人員 | 發布、監控及回滾模型 | 管理模型版本、閾值、漂移告警 |
| 專案管理者 | 掌握建築物與期間趨勢 | 檢視匯總、下載報告 |

典型流程：建立調查案件 → 上傳原始影像與中繼資料 → 影像品質檢查 → 平行呼叫適用專家 → 融合與分級 → 低信心／衝突項目人工複核 → 產出報告 → 校正資料進入資料集候選池。

## 3. 名詞與資料模型

| 名詞 | 定義 |
|---|---|
| 劣化類別（Deterioration Type） | 例如裂縫、缺失；為穩定且版本化的領域字彙。 |
| 專家（Expert） | 專責一類或一組緊密相關病害的模型、前後處理、閾值與品質規則。 |
| 觀測（Observation） | 一個專家在單張影像得到的可定位病害結果。 |
| 實例（Instance） | 同類且連通的病害區域；線狀裂縫可另以骨架／折線表示。 |
| 案件（Survey） | 一次調查任務，包含建築、構件、時間與影像。 |
| 複核（Review） | 人工對 AI 結果做接受、修正、駁回或無法判定的決策。 |

必要實體及關聯：`Monument 1─N Survey 1─N Component 1─N Image 1─N ExpertRun 1─N Observation 0─N Review`。每筆結果必須可追溯至原圖雜湊、前處理版本、專家模型版本與閾值設定版本。

## 4. 系統架構

```text
影像／中繼資料
       │
       ▼
攝影與品質閘門 ──(不合格)──> 要求重拍／人工處理
       │
       ▼
影像標準化與切磚 ──> 專家路由器 ─┬─> 裂縫專家
                                  ├─> 缺失專家
                                  ├─> 皺縮專家
                                  ├─> 龜裂專家
                                  └─> 起甲專家
                                           │
                                           ▼
                         標準化結果倉 + 融合／衝突處理
                                           │
                           ┌───────────────┴───────────────┐
                           ▼                               ▼
                    人工複核工作佇列                 報告／GIS／儀表板
                           │
                           ▼
                    經核准的回饋資料集 → 訓練、評估、模型登錄
```

元件責任：

- **攝影與品質閘門**：驗證格式、解析度、失焦、過曝、遮擋、比例尺與必要中繼資料；不合格影像不得進行正式風險判讀。
- **專家路由器**：依案件設定、構件材質、影像品質與專家健康狀態決定執行集合；預設執行所有已啟用專家，禁止因未偵測到結果而略過執行紀錄。
- **專家執行器**：容器化、無狀態的推論服務；各專家獨立擴縮與獨立發布。
- **融合器**：只做空間對齊、重疊關係、跨專家衝突及案件級彙整；不得擅自改寫專家的原始機率圖。
- **複核服務**：以原圖、疊圖、量測、模型版本與衝突原因支援可審計的人工決策。

## 5. 專家設計

### 5.1 專家登錄表

| expert_id | 類別 | 輸出型態 | 建議模型／後處理 | 初始狀態 |
|---|---|---|---|---|
| `crack-v1` | 裂縫 | 線狀語意分割 + 中心線 | 高解析切磚、連通元件、骨架化、最小寬度量測 | 可啟用 |
| `loss-v1` | 缺失 | 區域實例／語意分割 | 面積過濾、邊界平滑、深度／斜光資訊可選 | 可啟用 |
| `shrinkage-v1` | 皺縮 | 區域語意分割 | 少樣本策略、人工複核優先 | 試驗性 |
| `craquelure-v1` | 龜裂 | 紋理區域語意分割 | 多尺度切磚、紋理抑制、覆蓋率統計 | 可啟用 |
| `flaking-v1` | 起甲 | 區域實例／語意分割 | 面積與邊緣可信度過濾 | 試驗性 |

`shrinkage` 與 `flaking` 的現有正樣本量極低（分別為 3、19 張），不得在未補齊分組驗證資料前標示為可自動簽認；系統應以「候選區＋必須複核」方式提供結果。`stain` 的現有 18 張標註須先完成類別定義與標註一致性審核，再決定是否升格為正式類別。

### 5.2 專家共通契約

每個專家必須實作：

```text
POST /v1/experts/{expert_id}:infer
輸入：image_uri 或 image_bytes、image_id、preprocess_profile、tile_manifest、context
輸出：ExpertResult
```

`context` 至少含 `monument_id`、`component_id`、`material`、`capture_date`、`scale_mm_per_px`（未知時為 null）、`capture_profile`。模型不得把這些欄位當成不可追溯的隱藏規則；若有使用，須寫入輸出之 `decision_context`。

```json
{
  "schema_version": "1.0",
  "expert_id": "crack-v1",
  "model_version": "crack-resunet-2026.08.13",
  "run_id": "uuid",
  "image_id": "uuid",
  "status": "succeeded",
  "preprocess": {"profile": "rgb-v1", "tile_size_px": 1024, "overlap_px": 128},
  "observations": [{
    "observation_id": "uuid",
    "deterioration_type": "crack",
    "geometry": {"type": "Polygon", "coordinates": []},
    "centerline": {"type": "LineString", "coordinates": []},
    "score": 0.93,
    "metrics": {"area_px": 1240, "length_px": 388, "mean_width_px": 3.2},
    "severity": {"level": "moderate", "score": 0.58, "basis": ["length", "width"]},
    "review_state": "not_required"
  }],
  "artifacts": {"probability_map_uri": "...", "overlay_uri": "..."},
  "warnings": []
}
```

契約規則：座標一律以原圖像素座標表示；幾何採 GeoJSON；`score` 為校準後的 0–1 分數；空結果以空陣列回傳且 `status=succeeded`；失敗需有機器可讀錯誤碼；所有 URI 均以受權限控管的物件儲存位置提供。

### 5.3 專家內部管線

1. 載入並驗證輸入與預處理設定。
2. 以模型所需尺寸切磚；保留 tile 對原圖的可逆座標映射。
3. 執行推論，輸出原始機率圖／logits（保存為可追溯 artifact）。
4. 依專家設定完成拼接、閾值化、去噪、實例化與幾何量測。
5. 使用獨立校準集將 raw score 校準為置信度。
6. 套用專家專屬嚴重度規則，標註 warnings 與複核需求。

## 6. 影像、資料與標註規格

### 6.1 最低輸入要求

- JPEG、PNG 或 TIFF；保留原始檔，衍生圖不可覆寫原檔。
- RGB、最短邊至少 1,024 px；低於此門檻可執行候選偵測但必須標記 `low_resolution`。
- 至少一張含色卡／比例尺或可追溯相機校正資訊的同批次參考影像；無法量測時，僅報像素值與相對面積。
- 中繼資料：建築、構件、材質、拍攝時間、方位／位置（可得時）、拍攝者、相機、拍攝距離（可得時）。

### 6.2 標註規範

- 遮罩正式類別採既定五類；背景為 0，類別色碼與名稱由版本化 taxonomy 管理。`stain` 必須標記為 `candidate`，不得混入五類正式類別的訓練、驗證、測試或成效統計。
- 同圖多類共存合法；若原始格式不支援重疊，必須保留每類二值遮罩，另建立融合檢視層，不能因單一色碼而抹除重疊資訊。
- 裂縫與龜裂邊界準則需明確：孤立且主導方向明顯的長線狀破裂標為裂縫；密集網狀細紋區標為龜裂。無法判定標 `ambiguous` 並送專家裁決，不強迫標入任一類。
- 每批標註需至少 10% 雙人重標；計算每類 IoU／F1 與爭議率。未達門檻的批次不可成為驗證或測試真值。
- train、validation、test 必須依「建築／構件／來源群組」切分，禁止同一牆面或相鄰切磚跨集合，避免資料洩漏。

### 6.3 資料版本與血緣

資料集版本須記錄影像清單雜湊、標註版本、taxonomy、切分規則、標註者與審核狀態。模型訓練、評估、推論都必須引用不可變的 dataset/version ID；禁止以「最新資料夾」作為唯一依據。

## 7. 融合、衝突與風險分級

### 7.1 融合原則

- 專家輸出是來源事實（source of truth）；融合結果為衍生觀點，兩者都要保存。
- 同類多版本專家同時上線時，使用明確 canary／champion-challenger 規則，不取未校準分數的平均。
- 不同類別可以重疊：例如缺失上有龜裂或起甲。重疊本身不是錯誤。
- 只有 taxonomy 定義為互斥的類別才執行排他規則；本版五類正式類別預設皆可共存。

### 7.2 衝突規則

| 情況 | 處理 |
|---|---|
| 專家分數低於發布閾值 | 保留 artifact，不建立正式 observation；可在 QA 模式檢視。 |
| 分數介於候選與發布閾值 | 建立 `review_required` observation，送人工佇列。 |
| 裂縫與龜裂高度重疊 | 兩者皆保留，標記 `crack_craquelure_overlap`，由人工確認主導病害。 |
| 同類專家版本結果差異過大 | 以 champion 結果展示、記錄 challenger 差異，觸發模型監控告警。 |
| 影像品質不足或尺度未知 | 結果可展示但不得產生高風險自動結論。 |

### 7.3 嚴重度

嚴重度分為 `none`、`minor`、`moderate`、`major`、`critical`，必須同時保留可解釋的 `severity_score`（0–1）與 `basis`。規則由文資專家依構件類型設定，至少可使用：病害面積比、裂縫長度／寬度、病害數量、距上次調查的變化率、構件重要性、材質與含水／環境資訊。

預設保守規則：`critical` 一律人工覆核；沒有物理尺度時不得依裂縫寬度給 `major` 或 `critical`；模型的病害置信度與修復優先度不可混為單一分數。

## 8. 工作流程與狀態機

案件狀態：`draft → uploaded → quality_checked → inference_running → pending_review → approved | needs_reshoot | rejected → reported → archived`。

- 任一必要專家失敗：案件為 `pending_review`，不得靜默略過；允許重跑失敗專家。
- 任一 `review_required` 或 `critical` observation：案件必經人工複核後才能 `approved`。
- 複核可對每個 observation 執行 `accept`、`edit_geometry`、`change_type`、`change_severity`、`reject`、`cannot_determine`，並必填理由。
- 報告一經簽發即建立不可變快照；更正需產生新版報告與差異紀錄，不覆寫舊版。

## 9. 功能需求

| ID | 需求 | 驗收條件 |
|---|---|---|
| FR-01 | 批次與單張上傳 | 可上傳影像與必要中繼資料；每檔取得不可變 image ID 與雜湊。 |
| FR-02 | 品質檢查 | 產生可讀與可機讀品質報告；不合格原因可定位。 |
| FR-03 | 專家路由 | 每張圖記錄所有已啟用專家的執行／跳過／失敗狀態與原因。 |
| FR-04 | 專家推論 | 回傳符合 v1.0 契約的結果、疊圖及機率 artifact。 |
| FR-05 | 地理與構件彙整 | 可按建築、構件、日期、劣化類型篩選與統計。 |
| FR-06 | 人工複核 | 支援原圖／遮罩切換、縮放、量測、修改及審計軌跡。 |
| FR-07 | 報告 | 可輸出案件摘要、圖面、各類量化、嚴重度、模型與複核版本。 |
| FR-08 | 回饋閉環 | 經核准修訂可匯出成訓練候選資料，保留來源與授權。 |
| FR-09 | 模型管理 | 可上架、啟停、灰度發布、回滾專家模型與閾值。 |
| FR-10 | API 與匯出 | 提供案件、結果、幾何與報告的授權 API；支援 CSV、GeoJSON、COCO/遮罩匯出。 |

## 10. 非功能需求

- **效能**：在基準 GPU 上，單張 4K 影像、五個專家全跑的 p95 完成時間目標 ≤ 5 分鐘；前端先提供逐專家進度。實際 SLA 須以壓測結果確認。
- **可用性**：工作佇列具重試與冪等性；同一 `image_id + expert_id + model_version + config_version` 只能產生一個正式 run。
- **可擴充性**：新增專家僅需登錄、容器與契約測試；不得修改融合器核心流程。
- **安全與隱私**：原圖、位置、建築資訊採最小權限與傳輸／靜態加密；下載、刪除、簽認與模型發布寫入審計日誌。
- **可觀測性**：記錄延遲、GPU／CPU／記憶體、失敗率、空結果率、類別覆蓋率、score 分布與人工駁回率；每個 run 具 correlation ID。
- **可近用性**：介面支援繁體中文；影像疊圖可調透明度且非僅靠顏色區分類別。

## 11. 品質門檻、驗證與監控

### 11.1 發布門檻

每位專家在未見過的「建築／構件」測試集上驗證，至少報告 per-class precision、recall、F1、IoU、PR-AUC、校準誤差、每影像誤報率與置信區間。對裂縫額外報告中心線容忍 F1 與寬度量測誤差；對區域病害報告面積誤差與實例匹配率。

第一版的上線數值門檻由領域負責人依漏檢成本簽定，不在程式碼硬寫。任何門檻必須：有測試集證據、設定版本、核准人、有效期間與回滾條件。

### 11.2 線上監控與再訓練觸發

- 每週監看輸入解析度、色彩、材質、來源建築與預測分布的漂移。
- 任一類別人工駁回率、複核修正 IoU 或空結果率連續兩期超過基線警戒區間時，建立調查事件。
- 新增建築、材料、相機或拍攝條件後，必須先抽樣人工驗證再擴大自動化範圍。
- 再訓練資料只納入已完成授權與雙層品質審核的影像；重新訓練必須重跑固定回歸集，並與現任 champion 比較後才可發布。

## 12. 測試策略與驗收

| 層級 | 必測項目 |
|---|---|
| 單元測試 | tile 座標還原、遮罩拼接、面積／長度計算、閾值邊界、嚴重度規則、schema 驗證。 |
| 契約測試 | 每個專家對正常、空結果、低品質、失敗輸入皆符合 `ExpertResult`；未知類別與座標越界必須拒絕。 |
| 整合測試 | 五專家平行執行、部分失敗重試、融合重疊、複核後報告快照。 |
| 資料測試 | 原圖／標註配對、尺寸、類別色碼、群組切分無洩漏、重複影像與損壞檔案檢查。 |
| 回歸測試 | 固定 golden images 的幾何、分數區間、警告與報告內容不意外退化。 |
| 使用者驗收 | 調查員在真實案件完成上傳至簽發；文資專家確認病害語彙、複核體驗與報表適用性。 |

## 13. 分期交付

1. **MVP（裂縫＋龜裂）**：統一輸入、專家契約、非同步推論、疊圖、人工複核、基本報告；以現有相對成熟資料建立基線。
2. **多類擴展（缺失）**：加入缺失專家、重疊呈現、構件級統計與資料／模型登錄。
3. **少樣本類別試行（皺縮、起甲）**：補標與主動學習、候選模式、強制人工覆核；通過資料與評估門檻後才改為正式專家。
4. **候選類別裁決（汙漬）**：先完成領域定義、標註一致性與資料量評估；確認後才建立獨立專家與發布門檻。
5. **營運化**：GIS／案件整合、趨勢比較、漂移告警、canary 發布與完整審計。

## 14. 風險與決策紀錄

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 少數類別資料不足 | 高誤報／漏檢與虛假信心 | 維持候選模式、補樣本、採分組驗證與人工簽認。 |
| 不同拍攝光照／距離 | 跨現場泛化失效 | 攝影規範、品質閘門、色彩／尺度校正、跨建築測試。 |
| 相鄰切磚洩漏 | 離線指標虛高 | 強制以建築／構件群組切分並稽核索引。 |
| 劣化概念邊界不一致 | 標註噪聲、專家衝突 | taxonomy、標註手冊、爭議標籤與定期校準會議。 |
| AI 結果被誤作結構結論 | 文資與安全風險 | 明確用途聲明、critical 必覆核、報告保留限制條款。 |
| 模型悄然退化 | 錯誤累積 | 線上漂移、人工回饋指標、版本化及快速回滾。 |

## 15. 上線前決策清單

- 指定每類病害的文資領域負責人與標註裁決流程。
- 核定攝影 SOP、最小物理尺度與可接受的低品質例外。
- 為每類設定「候選」、「自動接受」、「必複核」三段閾值與漏檢／誤報成本。
- 補齊少樣本類別的標註與獨立測試組；確認各組皆無來源洩漏。
- 確認資料權利、保存期限、角色權限與建築位置的保密分級。
- 以至少一個真實調查案件完成端到端試營運，取得文資專家簽認後再正式啟用。
